review of the failed lean attempt. Implementation and the final integrated source
still require independent review before another bounded GPU run. No new GPU run
is admitted by this document or by the CPU fixtures.

The attempted lean profile at `3f06df192f1792ac4ddaaa58ee27628ac5665e57`
remains rejected: the client and both four-step traces completed, but one compiler
identity was first observed as an exited zombie with no argv/path/version proof.

do not prove what the unknown tool did or erase the rejection. The old packet,

The new `megartx-m1-decode-profile-plan-v1` schema binds the exact rule
`compiler_accounted_operation_diagnostic_v1`, controller and driver source hashes
and workload into its digest. It requires one warmup and one measurement per
stock/fused context, the same 2K/8K exact inputs and eight 256-token requests,
and the existing pinned metadata file guard. Plan, launcher CLI, client and actual
controller must agree that profiling is enabled. Missing/unknown intent, stale
digests or a larger pilot fail before dispatch. Ordinary eager plans retain their
previous schema, driver inventory and compiler timing gate.

Only this diagnostic's final branch calls `require_diagnostic_integrity()`.
It keeps latched resource/telemetry errors, pinned metadata file versions and
successful final hashes. The original owned-process observer, descendant RSS
and shared clock accounting, classification and sticky first-unknown histories
are unchanged. Ordinary timing still calls `require_compiler_quiescence()` and
rejects the same unknown/work histories after cleanup. No subprocess interception,
help-command synthesis, architecture caching or resource-cap increase is added.

The final diagnostic validates both complete four-step model/head/sampler
windows, 30 ordered preparation layers per frame, routed/correction frame counts,
native phase counts, preparation stream consistency, descriptor/route transfers,
fences and pointer queries. Every GPU operation needs exactly one CUDA API
correlation. A full inventory of operation names, launch geometry, shared memory
and transfer bytes must match the frozen prospective expectation. The stock
inventory comes from the accepted `2c65ebd` profile; the fused inventory is that
accepted fused inventory minus the 120 redundant 32-byte route copies predicted
by the lean source change. The failed lean packet supplies no accepted result.
Unexpected device work, graph events, missing/ambiguous correlation or identity,
shape/count/window/stream drift fails admission.

The same final branch rechecks bound build/control receipts, repository sources,
installed source/binary files and package versions, private AOT modules/shims and
receipts, and bridge bytes. The eight promoted incumbent AOT modules still cannot
be rebuilt; other ordinary JIT specs remain possible. Client input transcripts,
native dispatch and output usage, all within-context stock/fused warmup/measurement
token sequences, the six original forced BF16 fixtures and complete owned cleanup
must pass. Existing headroom, watchdog, primary-error and cleanup-error gates
remain active. Frozen target/checkpoint/postrun checks remain part of the reviewed
operational protocol before public diagnostic evidence can be accepted.

Successful diagnostics produce only operation counts, dispatch identities,
observed token equality and compiler-resource/cleanup scalars. All timing,
performance, quality and graph qualification flags stay false. The timing
summary reader rejects the diagnostic plan before reading any elapsed values,
even if trace directories or launch markers are removed or falsified on replay.
Raw traces and client elapsed fields stay private. They cannot become a clean
baseline, a speedup result, gap-cause attribution or general correctness proof.

CPU tests exercise intent/replay rejection, actual launcher final admission with
unknown zombie/work/descendant histories, retained clean-timing rejection,
resource and metadata-final failures, source/package/AOT/binary drift, and missing
or inconsistent trace/frame/layer/stream/correlation/count/token/fixture evidence.
Synthetic fixtures do not qualify native execution. Source/hash checks retain
their existing limits against transient changes; resource peaks are sampled.
Correction selection is outside the routed annotation, so its per-layer
attribution remains withheld. Stream wait operands/device wait durations are
unmeasured, and natural positive correction coverage must be reported separately.
